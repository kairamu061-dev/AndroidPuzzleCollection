# テストの線引き

**自動で回るもの**と、**実機で人が確かめるもの**の境目をここに書く。
`rules/automated-tests.md` の記録。

## いまの数字

| | |
|---|---|
| コード | {N} 行 |
| 自動テスト | {N} 行 / {N} 件（CI で**パッケージングより前**に走る） |
| テストケース一覧 | `docs/**/test-cases.md` |

## テストの置き場所

`rules/structure.md` のとおり `tests/` に置く。Gradle の既定 `src/test` ではなく、
各モジュールのテストソースをここへ向けている（`tests/sudoku-core` → `:sudoku-core`、
`tests/app` → `:app`）。実行は `./gradlew test`。

## CI で自動に回すもの（目標環境を要しない）

| 対象 | 守れる退行 | 状態 |
|---|---|---|
| 解法・解の個数 | **唯一解の判定**。ここが壊れると解けない問題が出る | 未 |
| 問題生成（シード固定） | 全難易度で唯一解・解と初期配置の整合・再現性・所要時間 | 未 |
| 難易度の判定 | 既知の問題が想定の段階に入ること | 未 |
| 盤面の操作 | 記入・メモ・消去・Undo/Redo・初期マスの保護・クリア判定 | 未 |
| 衝突の検出 | 行・列・ブロックそれぞれの境目 | 未 |
| タイマー | 中断と再開の境目で時間が増えないこと | 未 |
| 中断データの直列化 | 往復・形式の固定・壊れたデータの拒否 | 未 |
| 画面の遷移と操作（Robolectric） | 押して状態が変わる配線。実機の代わりではない | 未 |
| オフラインの保証 | 統合後のマニフェストに `INTERNET` 権限が無いこと | 未 |

## 実機でしか確かめられないもの（手の往復に残す）

**「なぜ自動化しないか」を必ず書く。**書けないなら、それは自動化できる。

| 対象 | なぜ自動化しないか |
|---|---|
| 実機の描画・タッチの感触 | Robolectric は実機の描画でもタッチでもない。指の大きさと比べたマスの押しやすさは人にしか判定できない。コンテナに `/dev/kvm` が無くエミュレータも動かせない |
| 端末差（画面サイズ・ノッチ・ナビゲーションバー） | 実機ごとのインセットの実測が要る |
| 実機での問題生成の待ち時間 | 自動テストは JVM 上の測定で、端末の CPU の速さを含まない |
| プロセスが OS に落とされた後の再開 | OS の振る舞いそのものを見る |

## 判定に使う道具

**製品自身に数字を言わせる**のが基本。推測の代わりに測定を置く。

| 仕組み | 何を分けるためのものか |
|---|---|
| 生成器のシード指定 | 「たまたま通った」と「どのシードでも通る」を分ける。失敗の再現にも使う |
| 生成器が返す試行回数 | 「遅い」の原因が 1 回の重さか、やり直しの多さかを分ける |
| 中断データの形式バージョン | 読めなかった理由が「壊れている」か「古い」かを分ける |
