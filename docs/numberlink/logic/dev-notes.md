## 実装上の判断

<!-- なぜその実装にしたかを記述する -->

| 判断内容 | 理由 |
|----------|------|
| サイズは 6×6 / 7×7 / 8×8 | **測った（JVM）:** 分割ありの生成で 9×9 は平均 315ms・最大 1.2 秒、10×10 は平均 12.8 秒。実機は JVM より遅いと見て（推測）、待ち時間に余裕のある 8×8 までにした |
| 2 つ目の解が見つかったら線を分けて端点を足す | **測った（JVM）:** 無作為に覆うだけでは 1 秒あたりの唯一解が 7×7 で 190、8×8 で 6.5（線の長さ上限 = 辺）。分けると 8×8 が平均 23ms になった |
| 隣り合う端点の線を最初から完成扱いにしない | 遠回りする解がありうる。総当たりとの照合で 2 解の盤面を 0 と数える誤りが見つかった |

## 今後の課題

- 線を分けて唯一にするため、8×8 で 10〜17 本と線が多めで短め。難しさが足りなければ、分割の少ない盤面を優先する
- 同じ数字の端点どうしが隣り合う問題が出る（線は遠回りする。規則上は正しい）
